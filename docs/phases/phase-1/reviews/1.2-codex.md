### Findings

1. **P2 · correctness · Persistent display-list churn can still exit 1.** `snapshot()` retries when the active IDs disagree with the online IDs or with per-display active metadata. But when a single Core Graphics list keeps changing between count and values reads, `queryDisplayIDs` exhausts its own attempts and throws `configurationFailed`. That bypasses the outer retry. A `list` command exits 1 for this case, despite the new documentation assigning 75 to a display setup that keeps changing. Phase 2 recovery would also charge it against the recovery attempt budget. The existing unstable-list test explicitly expects the generic error. The contract should cover this path or state which inconsistencies qualify. The timing wording should also say **three attempts total**, with two 20 ms delays. 2. **P2 · correctness · The Phase 1 design and plan overstate the recovery guarantees.** Both say a zero-active disconnect is rolled back. The brief requires a rollback attempt, and the implementation can skip that attempt on a runtime-ID conflict or leave the ledger entry when restoration fails. The design also says earlier-boot entries never trigger a mutation, but `connectAll` can enable a matching online inactive UUID using its current runtime ID. The boot restriction applies to the recorded ID of an offline display. These distinctions tell callers when they still need recovery after a failed command. The same section should identify the stored boot value as `kern.bootsessionuuid`. 3. **P2 · architecture · Phase 2 cannot filter same-boot re-cabling orphans with the planned row inputs.** The new design promises that those orphans get no row. `PanelRows.make` receives the snapshot, ledger and current boot. A valid D-005 ledger-only display and one re-cabled earlier in the same boot both appear as current-boot entries with an absent UUID. The ledger has no identity that links the old UUID to the new connection path. The planned boot filter can hide earlier-boot rows, but a same-boot orphan can still appear as an off switch whose connect operation fails.
