**Request changes before running the macOS 27 hardware matrix.** The watchdog now owns each disconnect worker, and the trial rejects watchdog-assisted recovery. The remaining blockers are a recovery path that can verify too early, watchdog deadlines that can be bypassed, a standalone trial that can outlive its limit, and an on-disk ledger compatibility regression.

## Findings

1. **P1 · architecture — Foreground recovery can declare success while a disconnect worker is still running.** If the watchdog exits unexpectedly, its `displayctl` child can survive. The foreground exit handler also falls back after a fixed wait if the watchdog is still alive. Both paths call `restore_loop` with an empty worker argument. A snapshot can therefore show both displays active just before the surviving worker commits its disable. The foreground then reports recovery verified. Recovery needs the same worker-quiescence guarantee regardless of which process performs it. [hardware-test.sh:147](/Scripts/hardware-test.sh:147) · [hardware-test.sh:432](/Scripts/hardware-test.sh:432) · [hardware-test.sh:447](/Scripts/hardware-test.sh:447)

2. **P1 · correctness — The watchdog can accept a late `YES` and miss its firing deadline.** `confirm_screen` computes the remaining time once, `ask` grants at least one second even when that time has expired, and the watchdog accepts an untimestamped `confirmed` marker. A `YES` written after the deadline but before the watchdog’s next poll suppresses firing. Separately, disarm verification runs before the deadline checks and can block in `list` for the full command timeout, delaying recovery and parent-death handling. The worker, confirmation, and recovery deadlines also use `date +%s`, so a backward clock adjustment extends them. The supervisor should enforce expiry using elapsed time and keep deadline checks active during verification. [hardware-test.sh:34](/Scripts/hardware-test.sh:34) · [hardware-test.sh:155](/Scripts/hardware-test.sh:155) · [hardware-test.sh:195](/Scripts/hardware-test.sh:195) · [hardware-test.sh:295](/Scripts/hardware-test.sh:295) · [hardware-test.sh:408](/Scripts/hardware-test.sh:408)

3. **P1 · correctness — Standalone `--trial` can keep a display dark past the requested limit.** The fix records the commit time and subtracts elapsed verification and output time from the eventual sleep. The code that exits the process still runs only after the post-commit display refresh and synchronous output writes return. A stalled refresh or blocked stdout can therefore keep the app-only configuration active past `--trial N`. The expiry needs to be enforceable while those operations are in progress. [ConnectionController.swift:316](/Sources/DisplayControlCore/ConnectionController.swift:316) · [main.swift:206](/Sources/displayctl/main.swift:206) · [main.swift:312](/Sources/displayctl/main.swift:312)

4. **P1 · correctness — Upgrading strands recovery records written by `d6b1997`.** The previous revision wrote `bootTime` to the same `disabled-displays.json` file. The new decoder requires `bootSession`, so one old entry makes the entire ledger unreadable. A display still hidden after a same-boot upgrade loses its saved recovery path. `connect all` can recover only online displays in that case, new disconnects fail, and `forget all` discards the saved identity. Preserve legacy entries for reporting and UUID reconciliation while treating their numeric IDs as untrusted.
