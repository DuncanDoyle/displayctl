## P1 findings

1. **P1 · correctness — The watchdog can certify recovery from a snapshot taken before the disable.** `restore_loop` reads the active set and then checks the mutator PID. A slow disconnect can commit and exit between those checks. The watchdog sees the old active set and a dead PID, declares success, and exits with the display disabled. There is a second window at launch, where the child starts before its PID is written. If the foreground dies in that window, the watchdog has no record of the pending disable. Register the operation before allowing it to mutate, and verify the active set after the worker is quiescent. [hardware-test.sh:26](/Scripts/hardware-test.sh:26) · [hardware-test.sh:63](/Scripts/hardware-test.sh:63)

2. **P1 · correctness — A watchdog timeout can be followed by another disconnect in the same run.** Final-display setup can issue several disconnects under one watchdog without checking whether it fired between launches. Also, if it fires during a round-trip reconnect, `restore_and_disarm` can clear `ARMED` after recovery and let the sequence continue. D-004 and §9.2 require the disruptive sequence to end after a timeout. Make firing terminal for the run and coordinate it with admission of each new disable. [hardware-test.sh:200](/Scripts/hardware-test.sh:200) · [hardware-test.sh:257](/Scripts/hardware-test.sh:257) · [hardware-test.sh:425](/Scripts/hardware-test.sh:425) · [hardware-test.sh:458](/Scripts/hardware-test.sh:458)

3. **P1 · architecture — The detached watchdog cannot enforce the mutation timeout after the foreground dies.** The foreground owns `run_bounded` and the signal to the worker. With the foreground stuck or killed, a live worker can keep the operation lock until the watchdog gives up, then complete its session-scoped disable. The watchdog has no way to stop that worker. The advertised recovery deadline also does not bound the `list` or `connect all` calls, and the timeout path sends `TERM` then waits without a further bound. The independent supervisor needs to own the worker’s lifetime as well as the recovery deadline. [hardware-test.sh:26](/Scripts/hardware-test.sh:26) · [hardware-test.sh:63](/Scripts/hardware-test.sh:63) · [hardware-test.sh:120](/Scripts/hardware-test.sh:120)

4. **P1 · correctness — Session-scoped recovery can make the app-only trial pass.** The trial watchdog can run ordinary `connect all` while the foreground is still waiting for the trial or polling `list`. If that restores the internal display, a zero trial exit and an active snapshot satisfy the gate even after the watchdog fired. The same recovery command can enable other, originally inactive displays with session scope. Treat any recovery intervention as a failed trial and keep the standalone reversion check independent of session-scoped recovery. The CLI’s claimed time bound also starts after postcondition verification and output, so a stall after the app-only commit can keep the display dark longer than requested. [hardware-test.sh:86](/Scripts/hardware-test.sh:86) · [hardware-test.sh:389](/Scripts/hardware-test.sh:389) · [main.swift:103](/Sources/displayctl/main.swift:103) · [main.swift:286](/Sources/displayctl/main.swift:286)

5. **P1 · architecture — An unclaimed ID in the online snapshot does not establish its current owner.** Offline reconnect and rollback accept the saved ID when the snapshot shows no conflicting online UUID. A different display can hold that ID while absent from the online list, or WindowServer can change the mapping between enumeration and mutation. The operation lock serializes this tool’s callers, and UUID verification occurs after the numeric enable. The amended rule catches visible collisions, but the stated invariant requires current identity evidence that remains valid through the mutation, or a skipped enable when that evidence is unavailable. [ConnectionController.swift:229](/Sources/DisplayControlCore/ConnectionController.swift:229) · [ConnectionController.swift:260](/Sources/DisplayControlCore/ConnectionController.swift:260) · [ConnectionController.swift:327](/Sources/DisplayControlCore/ConnectionController.swift:327) · [DisplayInventory.swift:135](/Sources/DisplayControlCore/DisplayInventory.swift:135)

6. **P1 · correctness — An unreadable ledger blocks recovery of online displays.** `connectAll()` loads and decodes the ledger before taking an inventory. A read or decode error therefore prevents every enable attempt, including recovery of online inactive displays whose current UUID and ID are available. The watchdog retries the same failing command. Preserve online recovery and report the ledger failure separately, without attempting saved IDs.
